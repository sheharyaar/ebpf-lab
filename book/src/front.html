How to read this

Five parts. The book follows one program, the write counter you wrote for your eBPF playground, kept with this book in program/maps/02-hash-map, through its life one stage a chapter, each stage read in the kernel's own source and measured. Part I takes it from C source to bytecode and into the kernel, Part II through the verifier, and Part III onto a hook, through the calls it makes and into its map. Part IV extends the kernel: memory a program manages itself, a set of programs that schedules the CPUs, and a new data structure built twice. Part V asks how the verifier's checks could be proved sound. The primer before builds the register machine that takes for granted; skip it if you already read assembly.

Two paths. Straight through is the intended path. The second path is by topic. Every reference carries a tag (lineageISAloaderverifierruntimeHW), and the references at the back are grouped by it.

Words. A word in bold is being defined in that sentence or the next. After that it is used without ceremony, and it is in the glossary at the back, under the chapter that defined it.

Figures. The figures are drawn in black and grey with one accent colour, a dark green. The accent marks the thing a figure wants you to watch, such as the path the counter takes or the one row that matters, and whatever it marks is also drawn heavier or dashed, so the figures read the same in greyscale. A figure that uses more than one kind of line names them in a legend.

The ribbon. The strip of dates under each chapter title is the history of eBPF by kernel version, drawn in full in the prologue. The entries set darker, with a filled dot, are the span that chapter covers.

Check yourself. Every chapter ends with two to four questions. Answer out loud first, in full sentences, then turn to the answer key at the back, where the answers are in chapter order. A question you can half-answer is the one worth re-reading the chapter for. If you would rather be quizzed properly, hand the book's source, the src folder beside it, to an agent running the Alvar probe skill and ask it to quiz you chapter by chapter: it asks through a real question tool, scores your reasoning rather than your letter, and writes what it found to .alvar/maps/.

Labs. Most chapters end with one lab, marked with its time and what it needs. Labs run from the book's program folder, whose make builds everything, and work on copies in /tmp, so the originals never change. Those that load a program need root: use sudo, or a throwaway virtual machine of your own kernel, vng -r /boot/vmlinuz-linux --user root, which is how the solutions were run. Each solution in the key says whether it was run, on which kernel and with which tools.

Line numbers. Every file and line of kernel source named in this book is from Linux v7.2, the kernel you run. They drift with every release; the chapter on the verifier's source shows how to find them again.

Printing. The pages you see are the pages that print. Print from Chrome with Margins: None, Headers and footers off and Background graphics on. Hints print in full, so cover them with a hand if you want to try first.
